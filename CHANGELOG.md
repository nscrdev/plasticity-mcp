# Changelog

## Unreleased

- `plasticity_export_obj` accepts optional `maxSides` (3..64), `convex`, `density`, `maxWidthMm` and `curveChordMaxMm` (each 0..1000 mm), passed to Plasticity only when given. `maxSides: 4` writes quad-dominant meshes (all quads at fine tolerance); larger values allow mixed quads and n-gons. The OBJ validator now also reports `triangleFaces`, `quads`, `ngons` and `sideHistogram`, and the result echoes `meshOptions`. The mesh written with no new options is unchanged; the sibling file behaviour below is new default behaviour.
- `plasticity_export_obj` new optional inputs, each passed to `OBJExportFactory` only when given: `perBody` (one OBJ per body; `path` is then an output directory and files are `<sanitised body name>_<body id>.obj`; to export a chosen subset into one file, list those ids with `perBody` false), `curveChordToleranceMm` and `surfacePlaneToleranceMm` (above 0 up to 10 mm, override the shared `chordToleranceMm` per side), `curveChordAngleDegrees` and `surfacePlaneAngleDegrees` (above 0 up to 90, override the shared `angleToleranceDegrees` per side), `planeAngleDegrees` (above 0 up to 90), `lockPlaneTolerance` and `lockAngleTolerance` (booleans; `true` is refused when the edge and face values differ, because the lock semantics are unverified), and `simplify` (Simplify Radial Surfaces, default false). The result echoes every applied option in `meshOptions` (including `simplify`).
- Behaviour change, on by default: OBJ export now keeps sibling files. Anything the native export writes next to `geometry.obj` (an `.mtl`) is copied beside the final OBJ under the OBJ's name (whitespace in the name becomes `_` for sibling files so `mtllib` stays a single valid name), `mtllib` lines are rewritten, and texture `map_*` references in the copied MTL are rewritten when they name a renamed file. A plain export can therefore write a second file, and is refused if `<stem>.mtl` (or any other sibling target) already exists. The result reports `mtl.written`, `mtl.paths`, `mtl.mtllib` and `siblingFiles`.
- OBJ export is now all-or-nothing. Every body is exported to a staging folder first, every target path (OBJ and siblings) is checked, non-regular siblings are refused, and files are finished in the staging folder and published by exclusive hard link (or a copy to a temporary name that is renamed into place), so a failed write never leaves a truncated target; anything this call already published is removed again if a later publish fails, and files that cannot be removed are named in the error. A failed export leaves no files (an empty output folder may remain). This also removes the leftover `.plasticity-obj-*` folders earlier versions could leave behind.
- `validateObj` reports `perObject` counts and bounds when a file has several `o` groups.
- `plasticity_chamfer` now rejects unknown keys (it is `.strict()`; extra keys used to be dropped silently). The equal-distance path is unchanged. `distance2Mm` (two-distance chamfer: `lockDistances = false`, `distance1`, `distance2`) and `mode` (`offset`, or `apex` via `ChamferMode.Apex`) are EXPERIMENTAL and refused unless `experimental: true` is passed. They cannot be combined. The result then carries an `experimental` block with the values sent as `distance1` and `distance2`. The sign convention, which face gets which distance, and the Apex meaning are unverified.
- New EXPERIMENTAL tool `plasticity_fillet_variable`, refused unless `experimental: true` (schema-required literal): base `radiusMm` plus `points` of `{edgeId, radiusMm, t (0..1) | pointMm}`, mapped to `FilletShellFactory.addVariationPoint`. The argument order of `addVariationPoint` is inferred from its declared arity of 2 (point, radius in metres) and the call is refused if the arity differs. `pointMm` is projected onto its edge by dense sampling of `GetPointAndTangent` and refused when more than 0.05 mm away; both paths hand the native edge position object to `addVariationPoint`, and the result returns the resolved `t`, point and distance for every variation point. After commit the body's face count and blend-face count are compared with the state before (face ids are revision-bound, so ids are never compared), and the call fails unless both increased; new blend faces are reported by centre and radius. It cannot yet check the radii themselves.
- New experimental tools for Plasticity Studio surfacing. None of the native argument names could be read without constructing a factory, so each tool checks that every field exists and stores the value (set inputs first, then options, then re-read every field right before commit) and fails loudly otherwise. Read-back proves a field exists and holds the value; it cannot prove that commit honours it or in which unit. The tools return the values READ BACK from the factory in `appliedOptions`, not the requested ones. All are unverified against a live Plasticity.
  - `plasticity_polysplines_from_reference_mesh`: `referenceMeshIds` (1..16, OBJ or FBX meshes only; STL, 3MF and unknown-source meshes are refused), optional booleans `roundedCorners`, `mergePatches`, `interpolateBoundary` (passed only when given). Uses `ConvertMeshToPolySplinesFactory`; fails when no body appears and returns `partial: true` with `outcome` details when fewer bodies than input meshes appear.
  - `plasticity_import_polysplines`: `path` (.obj or .fbx), `sourceUnit` (millimeter, centimeter, meter, inch, foot), same three booleans. Uses `ImportPolySplinesFactory`; `filePath` and `unit` must exist and read back, otherwise it refuses and points to the reference-mesh route. A `unit` that exists but is ignored cannot be detected: verify the returned bounds. Partial conversion of a multi-mesh file cannot be detected.
  - `plasticity_create_xsided_surface` (XNurbs): `edges` 3..64 of `{bodyId, edgeId, continuity?}`, optional global `continuity` (G0..G3), `uDegree`/`vDegree` (integer 2..11), `uSpans`/`vSpans` (integer 1..64), `quadSided` (requires exactly 4 edges), `toleranceMm` (greater than 0, at most 10; sent in metres, an UNVERIFIED unit, and refused when the factory default looks like millimetres). The boundary must be one closed loop checked from vertex positions; without vertex data the call refuses (`loopCheck` is returned). Success requires a new Sheet or Solid, or an input body that gained faces, judged from the scene diff; a commit that only moved the undo stack fails and reports what changed. Global continuity is verified on every edge without its own override.
  - `plasticity_set_shader_mode`: optional `mode` (matcaps, isophotes, draft, zebra_horizontal, zebra_vertical, topo, face_direction); omit to read the current mode. Locates the Shader mode panel container first (refuses when it is not mounted, when several containers qualify, or when a mode matches more than one button), sends exactly one click, reads the active mode back and reports it, and fails if the document revision changed. It uses the read path, so it bypasses the `uncertain` mutation guard; the `data-state="active"` marker is unverified live.

### Live-verified status

Live-verified: none of the new options. Earlier live runs exercised only `maxSides`, `convex` (no visible effect on quad output) and the shared tolerances. The live tests below (numbering from the independent review) would confirm:

- L1 lock flags: the native value type of `lockPlaneTolerance` / `lockAngleTolerance`, and whether "lock" means the face value follows the edge value. Until then the schema stays boolean and lock `true` with differing values is refused.
- L2 `maxWidthMm` / `curveChordMaxMm`: that they are in metres as sent (mm in the API), that `0` means no limit, and what they do to face and chord counts.
- L3 MTL: that Plasticity writes an `.mtl` beside the staging OBJ, that `mtllib` and `usemtl` lines survive the copy and rename, and that Blender or Houdini load the materials.
- L4 `perBody`: one `o` per file, name sanitising, and each file's bounds matching its body.
- L5 two-distance chamfer: that legs measure `distanceMm` and `distance2Mm`, that the negative sign is right, and which face gets which distance per edge.
- L6 apex chamfer: what `distanceMm` means in apex mode, and that `offset` equals no mode.
- L7 variable fillet: the real argument order and type of `addVariationPoint`, that commit uses the variation points, and that the radii near the ends match the request.

Known limits: two sibling files with the same extension abort the export after the native write; `perObject` keys on `o` only (`g` groups ignored); a `mtllib` line listing several libraries is not rewritten.

### Not exposed

- OBJ Remove Small Features, Inflect and Min Width: no native accessor with a matching name exists on `OBJExportFactory` (read from the live 26.1.3 prototype), and the factory source is obfuscated, so the field names cannot be confirmed without constructing the factory.
- OBJ `empties` (instance empties): it is an accessor, but it takes native instance-empty views filled through `addInstanceEmpty`, not a plain value.
- `lockPlaneTolerance` and `lockAngleTolerance` are exposed, but their value type could not be read; boolean is assumed and the meaning is unverified (see Live-verified status).
- Variable-fillet limit points (`addLimitPoint`, arity 3): argument meaning not readable.
- Full round fillet (`fullRound`, `isFullRoundPossible`): `FilletShellFactory` has no settable flag that selects it (`mode` is a getter), so there is no verified way to trigger it. Not implemented rather than guessed.
- Fillet shape, `yBlend`, `rho` and Tension: these accessors exist only on `MultiFilletShellFactory`; the MCP uses `FilletShellFactory`.
- Align Surfaces: `pairs` and reference formats are not readable.
- Square fill: the `boundaries` shape is not readable.
- Refit and Explicit Control on Rebuild Face: the factories expose no degree, spans or tolerance accessors with known names.
- Multi-fillet (`MultiFilletShellFactory`): no `shell` accessor and the tension field is not on the prototype.
- Curvature display is a separate overlay, not a shader mode.

## 0.2.1 — 2026-09-28

- First GitHub release of the local preview for Plasticity 26.1.3 on macOS Apple Silicon. See the [acceptance matrix](docs/acceptance-matrix.md) for verified operations and remaining limitations.
